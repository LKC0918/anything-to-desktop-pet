# 形象、动作与素材

在设计玩法、制作/提取素材或排查帧间跳变时阅读。桌面窗口与验收见 [desktop-runtime-and-validation.md](desktop-runtime-and-validation.md)。

## 让对象的特征产生玩法

先找到「看一眼就认得出」的特征，再把它和用户的一次桌面操作连接。外观、行为和用途至少有一项来自原对象，不必给所有东西加眼睛、脚或随机台词。

| 对象特征 | 可解释的动作 | 可连接的桌面事件 |
| --- | --- | --- |
| 水壶会蓄热、沸腾、冒汽 | 壶盖抬起，蒸汽喷出，再安静落下 | 番茄钟结束、用户点击提醒 |
| 回形针夹住纸张 | 张开、夹住、拖到一边 | 接收用户拖入的待办卡片 |
| 灯泡亮起 | 由暗变亮、闪一下 | 专注开始或任务完成 |
| 游戏射手发射弹丸 | 蓄力、发射、命中、退场 | 用户明确选择的目标操作 |
| 有经典动作的角色 | 保留原姿势与原声关键点 | 点击反馈、日程提醒、消息到达 |

只实现当前请求需要的动作。两项目的喊妈妈、摘角变身、草块和僵尸担架不能作为任意桌宠的固定动作库。

## 一个完整例子：水壶桌宠

用户给一张透明水壶 PNG，要求「放在桌角，点击烧水，25 分钟后提醒」。

- **准备**：保留原图；记录壶嘴方向、壶身颜色、共同画布与壶底锚点；先核实透明度。没有盖子分层时不伪造开盖逐帧素材。
- **连续步骤**：透明桌面小窗显示静止壶 → 拖动改变位置 → 点击开始专注 → 用程序绘制独立蒸汽或轻微位移 → 计时结束显示气泡 → 可重置/暂停/退出。
- **展示结果**：可运行应用，菜单里有「立即测试提醒」，25 分钟是配置值。说明蒸汽是程序效果、壶图是静态素材，计时提醒在本机运行；没有联网消息集成。

先让这个闭环可用，再根据需要制作壶盖动作、原声或其他状态。若对象本来不能自行行走，可用滚动、滑动、弹跳、停靠等合理反馈，不强行套四足走路。

## 素材路径

### 单张图、文字与新素材

1. 列出少量不可变项：轮廓、配色、身体比例、面部/标识、材质、朝向。动作参考只提供姿势，不改变角色身份。
2. 用户明确提供现成形象时，优先保留；需要新的位图、角色动作或去背景时使用可用的图像工具。不得把“统一风格”当作擅自重画原角色的理由。
3. 单图可以先用于拖动、点击位移、旋转和程序效果。生成真实多帧时每帧需重新验收，不将同一图轻微缩放命名为完整行走循环。
4. 提示词按需包含：同一角色、同一画布/镜头/地平线、全身不裁切、动作起止、朝向、不含文字标签、真正透明背景。帧数由动作需要决定；16 帧和 4×4 只是牛来项目的选型。

### GIF、序列和图集

- GIF/WebP 的原始帧时长、循环、透明与 disposal 合成可能影响显示。保留源元数据；0 或缺失时长单独报告，若运行时需要兜底帧率，明确该选择。
- 序列按自然数顺序排列；运行时加载不能悄悄跳过缺帧，再把剩余帧当完整序列。将帧清单、顺序、循环与事件点放到一个明确配置中。
- 图集先查看真实行列、留白、分隔线和偏移。生成图常不是精确网格；允许每格显式 crop rect。不能用平均等分掩盖被切断的尾巴、耳朵和道具。
- 不逐帧分别裁到各自 bbox 再填满窗口；这会改变角色比例和落点。先定共同逻辑画布与锚点，再按统一缩放放置。不同动作可有不同画布，但需保留角色身体尺度和锚点变换。
- alpha bbox 是非透明边界，不是骨骼或脚底的语义识别。脚底有阴影、尾巴或蒸汽时，不要用 bbox 底边直接代表脚掌。
- 用明显动作事件复核顺序：吃掉的物件应持续减少；变身先发生必要前置动作，再出现完整结果；循环首尾不能突然跳变。可重排或剔除错误帧，并记录原因。

### Scratch 原档

使用 `scripts/pet_assets.py scratch` 先检查目标与 costume/sound 清单；必要时 `--target` 精确过滤后提取。支持 sb2/sb3/sprite2/sprite3。归档只作为资源容器，不运行积木或扩展代码。

保留 target、原始 index/name、资源文件名/hash、位图倍率和旋转中心。不同 costume 的 rotation center 可能不同，不能假设画布中心就是锚点。需要转换时依据元数据统一坐标，保留源文件与派生图映射；SVG 栅格化是后续步骤，不把扩展名改成 PNG。

豌豆射手项目记录了每个动作来自哪个 costume，并剔除一张锚点不兼容的僵尸帧。可复用的是检查与来源映射方法，不是归档文件名、hash、特定帧号或裁切坐标。

Scratch 3 元数据字段可核对 [Scratch 官方序列化实现](https://github.com/scratchfoundation/scratch-vm/blob/develop/src/serialization/sb3.js)，重点 `serializeCostume`、`serializeSound`。源码可能演进，遇格式差异应看实际归档，而非凭旧文档猜字段。

## 质量检查与来源记录

`pet_assets.py audit` 可读取单图、GIF/WebP 或目录当前层的图片，输出 `inventory.json` 和深浅背景联系表。先运行 `--help` 查看当前限制。目录检查不是完整工程资源审计；音频、SVG、图集分格与语义锚点仍需相应工具或人工检查。

观察深浅两种背景，检查白边、黑边、假棋盘底、透明孔洞、裁切与残留标签。工具提示“没有透明像素”只证明 alpha 现状，不能判断背景究竟是白底还是棋盘；有透明像素也不能证明轮廓已正确。

声音用实际媒体时长和可验证播放结果；把发声点绑定到 `mouthOpen`、`impact`、`transformComplete` 等事件。动作被取消时同步停声音。不要每帧重启音频，也不要从源文件长度推断声音一定已播放。

项目内的素材记录可很短，但要能回答：从哪来、是否改过、当前加载哪版、属于哪个动作、有没有使用限制。当前用户自用桌宠可使用用户提供的素材；请求分享技能时不携带私人音频、品牌角色图或原始游戏归档。公开分发应用时再核实所含素材的来源与使用条件。
