# 桌面运行与验证

在实现窗口、状态协调、工具联动、构建或验收时阅读。本文件以两个 macOS 工程为经验基线；其他平台需要验证自己的原生窗口与系统集成。

## 窗口与输入

| 模式 | 可借鉴的结构 | 要验证的行为 |
| --- | --- | --- |
| 常驻陪伴 | AppKit 透明无边框小窗、适当 floating 层级、菜单栏入口 | 拖动与点击区分；不抢主窗口；隐藏后可找回；关闭终端后独立启动 |
| 按需召唤 | 非激活透明演出层，独立确认/按钮层 | 全屏演出不截断桌面点击；确认可点；结束后所有临时窗口释放 |
| 复杂动作 | 场景图如 SpriteKit；共同父组、相对锚点与统一场景时钟 | 骑乘/搬运保持接触；整体翻转后局部不反向漂移 |

macOS 可参考 `NSPanel` 的 borderless/nonactivating 组合、`isOpaque = false`、透明背景、`hidesOnDeactivate = false`，按实际需要设置窗口层级和 Spaces 行为。不要使用系统安全界面之上的窗口层级。输入文本的设置窗与非激活演出层需求不同，分别处理焦点。

普通小窗的交互命中范围与角色相符；空白/透明部分的穿透需在目标环境实际检查。只给 NSView 返回 nil 不能未经验证就声称整窗已穿透。全屏演出层可设 `ignoresMouseEvents`，可交互按钮放另一个小窗。

自定义角色视图应有可识别的辅助功能标签、角色与窗口标题，便于辅助工具定位。坐标驱动报错时，先区分工具命中失败与程序事件失败；不能因为工具没发出拖动事件就宣称拖动实现坏了，也不能把代码检查补写为拖动实测通过。

官方 API 入口：[NSPanel](https://developer.apple.com/documentation/appkit/nspanel)、[nonactivatingPanel](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel)。这些链接用于查当前 API；项目里的具体实现和实际桌面表现仍要分别核对。

## 坐标与比例

- 为屏幕全局坐标、窗口局部坐标、场景坐标与图像像素标清边界。多屏可有负 origin；先确定目标屏幕，再转换。不要把屏幕像素直接当 AppKit 点。
- 常驻位置保存后按连接的屏幕 `visibleFrame` 恢复到可见区；屏幕变化后重新处理。临时目标演出可允许透明画布部分出屏，以保持目标锚点在真实图标上，结束后恢复常驻位置。
- 目标锚点必须有来源：请求中的文件身份与图标位置、AX 范围、原始右键点等。菜单项点击后的鼠标位置通常已偏离目标。无法定位时显示限制或请用户选择位置，不能静默冒充“精确定位”。
- 角色外观缩放基于身体与共同画布；点击反馈可偏移/弹跳，不应无意改尺度。气泡文字独立保持可读。
- 点击反馈同时测试普通位置、顶边和角落。向上位移被顶边限制时可改向下反馈或使用原位效果，不能把位移钳制成零后仍声称有可见反馈。拖动释放不应再误触点击动作。
- 发射口、抓取点和骑乘脚掌用归一化局部锚点。组合动作先绑定父组，再整体移动、缩放与翻转；避免多条定时器分别追逐位置。

## 流程协调

最小陪伴流程可以是 `idle → reacting → idle`，工具流程按需增加 `appearing → approaching → awaitingConfirmation → acting → committing → success/failure → exiting`。状态名和状态数量不是固定要求；约束是每次演出只有一个有效流程，副作用只执行一次。

- 用合法迁移或等价的明确流程检查阻止重复开始、重复确认和重复提交。
- 每条流程带 generation/token 或等价取消句柄；所有延迟回调、移动 completion、声音事件和实际操作入口都验证当前流程仍有效。只在最外层做一次 token 检查不够。
- 取消/退出清理计时器、动画、气泡、音频、窗口扩展和输入状态。暂停若只暂停动画，应在产品中明确；承诺完整暂停就冻结或取消整个流程，并以同一时间基准恢复。
- 副作用已提交后不能通过隐藏动画假装撤销。恢复动作需要单独真实实现与结果提示；状态未知时先核实，不能盲目重试。
- 静止待机停止不必要重绘；随机行为只在可见、未暂停、空闲时触发。低频生活动作和轻微呼吸由对象特性与用户偏好决定，不沿用项目中的固定秒数。
- 音画共享事件表/时钟：例如关键帧出现时播放原声，按实际时长结束；不要把多个独立 `asyncAfter` 常量堆成不可取消的流程。

## 可选能力适配器

把外部能力放在可注入接口后：时钟、音频、消息接收、发送、文件操作、定位、打开外部应用。每个动作可在测试菜单或命令入口立即触发。

**消息与提醒**：分别记录「模拟事件」「真实接收」「本地草稿」「真实发送」。可用连接器不代表已登录；收到消息不代表能发；打开客户端不代表已经发送。只实现用户请求的能力，不为了普通桌宠自动启用后台消息监听。

**文件玩法**：

- 演示请求不带真实 URL，动画层不自行找文件。真实请求走能力适配器，在可识别目标的确认界面后才操作。
- 对所有入口统一检查选择数量、类型、允许范围与符号链接策略。若仅支持单选，拖入多选也要拒绝或明确让用户选择，不能用 `.first` 偷换目标。
- 确认后执行前重检身份；对可替换路径可保存设备号/inode 等身份并在协调操作中比较。不同产品不必复制射手的全部目录限制，但不能只依赖路径字符串或入口检查。
- 清理使用系统废纸篓，无永久删除兜底；成功返回后才最终碎裂/吃掉并显示成功。失败、权限缺失、目标变化都终止成功分支。
- 应用内撤销只有真正保存废纸篓结果 URL、原位置并处理重名后才可宣称；单纯可在系统废纸篓手动恢复应如实标明。跨重启恢复需要持久记录，不能拿进程内数组声称已支持。

官方 API：[FileManager.trashItem](https://developer.apple.com/documentation/foundation/filemanager/trashitem(at:resultingitemurl:))。不要用直接文件删除模拟“回收”。测试只能操作本次创建的样本，不能清空废纸篓。

## 构建与验证记录

沿用工程自己的构建方式：轻量 Swift Package 或带扩展的 Xcode 工程。先检查工具链与依赖，再使用当前工程的命令；两个项目的绝对路径、产品名、架构和脚本不可原样硬编码到新项目。

运行时从应用 bundle 读取打包资源，并让开发模式的覆盖路径显式可控。构建时检查实际使用的所有帧/声音，不能只检查每组首尾两帧。派生资源命令必须确实生成当前版本，不要沿用牛来旧预处理命令生成错误目录。

把 build、bundle、package、install 分开。安装可能覆盖现有 app、注册 Finder 扩展/服务、终止程序或重启 Finder；不要把这些副作用藏在普通 smoke test。用户已明确要求安装时按该范围执行，不重复索取已给授权。

本机临时签名、Developer ID 签名、Apple 公证分别报告；不要为了启动成功修改系统安全设置。通用二进制含两种架构不等于两种硬件都实测。需要跨机分发时按当时官方流程检查签名与公证。

一次验证记录至少回答：

| 层级 | 可观察证据 | 不能推出的结论 |
| --- | --- | --- |
| 资源/构建 | 帧清单、缺失检测、编译与 bundle 结果 | 真实桌面体验正确 |
| 隔离逻辑 | fake clock/adapter 下的状态、取消、失败、重复触发 | 真实消息与系统权限可用 |
| 桌面演示 | 实际启动、点击、拖动、暂停、退出、音画与输入恢复 | 真实文件或发送链路已通过 |
| 真实能力 | 新建样本的真实结果、权限入口、身份与恢复核对 | 所有入口/系统/架构都已验证 |

按本次改动挑相应检查。纯文案或轻微样式无需堆完整测试套件；状态/副作用修改需要覆盖失败、中断和重复操作。无法自动观察的权限面板或真实客户端行为，保留清楚的人工步骤与未验证状态。

基础 GUI 验收至少覆盖：真实鼠标拖动前后的位置变化；点击后的可见反馈与回位；隐藏后从菜单栏恢复；暂停时动作停止且菜单状态一致（如保留拖动须明确）；退出后窗口、菜单项与进程消失。短动画容易被截图错过，可用录屏或仅在测试模式开启的本地事件记录，记录实际窗口 frame 和事件来源，不能只记录模型目标值。系统权限不足时明确停在权限边界，不改系统保护，也不把模拟事件注入模型冒充真实桌面输入。
