# 两类桌宠的制作经验

本技能从常驻陪伴和按需召唤两类桌宠工程中提炼方法。使用技能不需要原始工程；公开包不附带它们的应用工程、声音或游戏素材归档。页面中的奶娃图片只用于展示样例。

## 案例一：常驻陪伴桌宠

角色平时安静待在桌面上，通过点击、拖动、日程或消息事件进入一段动作，结束后回到待机状态。

可复用的方法：

- 透明无边框小窗负责角色展示，菜单栏提供显示、隐藏、暂停和退出入口。
- 以移动阈值区分点击与拖动，拖动结束后保存位置；重启或屏幕布局变化后恢复到可见范围。
- 静止待机停止不必要重绘；自主行为只在空闲、可见、未暂停时开始。
- 用共同画布、身体尺度和动作锚点保持形象稳定，不因换帧或点击反馈忽大忽小。
- 以动作事件触发声音，按实际音频时长结束；中断时同时处理计时器、声音、移动和气泡。
- 超出小窗范围的演出临时切换到演出层，完成后恢复小窗、位置与输入状态。

消息功能需要分别记录模拟事件、真实接收、本地草稿与真实发送。存在连接代码或能唤起客户端，都不能单独证明消息已接通或已经发出。

## 案例二：按需召唤的工具桌宠

角色由用户从菜单、拖放或文件入口召唤，走向指定目标，执行动作或工具能力，展示结果后退场。它不必一直留在屏幕上。

可复用的方法：

- 透明演出层穿透鼠标，确认按钮放在独立的小交互层，避免动画挡住整屏工作。
- 用明确流程协调出现、接近、确认、执行、成功或失败、退场，阻止重复触发副作用。
- 演示请求不携带真实文件目标，工具能力通过独立适配接口注入。
- 目标身份与位置一起核对；图标位置、原始右键点和菜单点击点有不同含义，不能互相冒充。
- 系统操作成功后才播放最终成功结算；失败时停止成功分支并显示可理解的结果。
- 多角色搬运或骑乘绑定同一父组，再整体移动与翻转，保持接触点稳定。
- 游戏素材按造型清单提取，保留来源映射、旋转中心和位图倍率；异常帧单独调整或排除。

文件清理可以使用系统废纸篓，但应用内撤销需要另外实现并验证。能手动从废纸篓恢复，不等于应用已经支持一键撤销。

## 不应照搬的内容

角色的经典台词、变身顺序、动画帧数、随机动作间隔、确认次数、攻击次数、固定尺寸和目录限制，都是具体产品的选择。新桌宠应根据对象特征、用户需求与实际风险重新决定。

从旧工程中复用方法时，应核对当前入口和实际加载的资源，不继承过时的说明、测试数量或“全部实测”结论。

本次使用技能制作的单张 PNG 桌宠样例已完成本机 GUI 验证，结果与范围见 [公开验证说明](https://github.com/LKC0918/anything-to-desktop-pet/blob/main/docs/verification.md)。这份结果不代替新桌宠的逐项验收。
